# Cover statement

For this capstone I chose Option B and built a new artifact: the Duo Game Data API, a read-only companion service for my Roblox monster-taming game. It serves the game's exported balance data and re-implements its stat, experience and damage formulas, but the real subject is the delivery system around it. Game data moves from Roblox Studio into Git through a verified one-paste import, is validated on every pull request, and ships inside an immutable container image. The project demonstrates pipeline design with layered quality gates, shift-left security with gitleaks, pip-audit and Trivy, repeatable infrastructure as code with Docker Compose environments, observability as code with tested Prometheus alerts and a provisioned Grafana dashboard, and GitOps-style promotion from staging to an approval-gated production. In an interview for a platform engineering or SRE role at a live-service game studio, I would open with the problem: content changes break live games as often as code does. I would then walk through one balance change from Studio export to production, show the dashboard under a real load test, and explain the measured limits and what I would build next.
